# rakuten-x-poster

楽天アフィリエイトの人気ランキング商品を、毎日自動で「投稿案プール」として用意する専用Webアプリ。
**Xへの投稿自体は手動**(Webアプリの「𝕏で開く」で投稿画面を開いて自分でポストする)。

## 使い方(完成後のイメージ)

`https://<あなたのアカウント>.github.io/rakuten-x-poster/` をスマホのホーム画面に追加しておく。

1. 毎日自動でおすすめ商品カードが補充される(通常ランキングに加えて、セール中・急上昇中もタグ付けされる)。加えて「5と0のつく日」等、特定商品に紐づかない楽天のお得情報カードも該当日には追加される(インプレッション・閲覧数アップ目的。アフィリエイトとは無関係)
2. 上部のタブで「すべて / 🏆ランキング / 🔥セール / 📈急上昇 / 💬口コミ人気 / 💡お得情報」を切り替えて見たいものだけ表示できる
3. カードの「𝕏 で開く」を押す → 投稿文が入った状態でXの投稿画面が開く → 内容確認して投稿
4. 投稿し終わったら「✅ 投稿済みにする」を押す
   - デフォルトではその端末だけに記録される(他の端末には反映されない)。
   - 「⚙️ 同期設定」でGitHubのトークンを登録しておくと、投稿済み状態がこのリポジトリの `docs/done.json` に保存され、**PC・スマホなど複数端末間で同期**される(重複ポスト防止。詳細は後述)。

---

## なぜ完全自動投稿にしないのか

楽天アフィリエイトの[公式ガイドライン](https://affiliate.rakuten.co.jp/guideline/rule/)には、
「スクリプトや外部プログラムを使い、機械的に投稿やコメントを行う行為」を禁止する規定があり、
実際に警告を受けた事例も報告されている([参考記事](https://note.com/etc_999/n/n64862c4ad6de))。
違反するとアカウント停止・報酬没収のリスクがある。

そのため、このツールは**投稿文の作成まで**を自動化し、実際にXへ投稿するボタンを押すのは人間(あなた)にしている。
これにより:
- 楽天の禁止事項(機械的な自動投稿)に抵触しない
- X Developer Portalでのアプリ申請・APIキー取得が不要になる(投稿用APIを使わないため)

## 1. 必要なもの

### 楽天API
1. [楽天ウェブサービス](https://webservice.rakuten.co.jp/) にアプリ登録し、**アプリケーションID**と**アクセスキー(`pk_`から始まる文字列)**を取得する(アプリケーションタイプは「WEB」、許可されたWebサイトは投稿先のXアカウントのドメイン`x.com`など)。
   - 2026年のAPI移行により、この2つがセットで必須になった。
   - APIリクエストには、登録した許可サイトと同じ`Referer`・`Origin`ヘッダーの両方が必要(`src/rakuten.js`で対応済み)。
2. [楽天アフィリエイト](https://affiliate.rakuten.co.jp/) に登録し、**アフィリエイトID**を取得する。
   - これが無くても動くが、無いと成果報酬が発生しないリンクになるので必ず取得すること。

### X (Twitter) アカウント
- 通常のXアカウントがあればよい。API申請は不要。

### Google Gemini API(任意・AIコメント機能を使う場合)
1. [Google AI Studio](https://aistudio.google.com/apikey) でAPIキーを発行する(Googleアカウントがあれば無料で取得可能)。
2. 無料枠のあるモデル(`gemini-3.7-flash`)を使っているため、この程度の利用量(1日数件)なら実質無料で運用できる見込み。
3. 設定しなくても動く(その場合はAIコメント無しの従来テンプレートで投稿文が作られる)。

## 2. ローカルで試す(任意)

```bash
npm install
cp .env.example .env
# .env に RAKUTEN_APP_ID / RAKUTEN_ACCESS_KEY / RAKUTEN_AFFILIATE_ID (/ GEMINI_API_KEY) を書き込む(DRY_RUN=true のままなら投稿案はコンソール表示のみ)
npm start
```

`DRY_RUN=false` で実行すると `docs/pool.json` が生成される。`npx http-server docs` などでローカル確認できる。

---

## 3. GitHubにpush・Pages公開・Actions自動化

1. GitHubリポジトリを作りpush、Secretsに `RAKUTEN_APP_ID` / `RAKUTEN_ACCESS_KEY` / `RAKUTEN_AFFILIATE_ID` (/ 任意で `GEMINI_API_KEY`) を登録する。
2. **Settings > Pages** で、Source を「Deploy from a branch」、Branch を `main` / `docs` に設定して保存する。
   - 数分で `https://<あなたのアカウント>.github.io/rakuten-x-poster/` が公開される。
3. **Actions** タブ → `Rakuten Affiliate Pool Refill` → **Run workflow** で手動実行して動作確認する。
   - `dry_run` を `true` にすれば `pool.json` を更新せずログだけ確認できる。
4. 成功すると `docs/pool.json` が更新・commitされ、Webアプリに反映される。
5. 問題なければ毎日 `.github/workflows/daily-post.yml` の cron (`0 12 * * *` = 毎日21時JST) で自動的にプールが補充される。

## 4. カスタマイズ

`config.json` を編集する:

```json
{
  "genres": [
    { "key": "general", "genreId": "0", "genreLabel": "総合", "poolSize": 2, "trendingPoolSize": 2, "popularPoolSize": 1 },
    { "key": "subculture", "genreId": "101164", "genreLabel": "サブカル", "poolSize": 1, "trendingPoolSize": 1, "popularPoolSize": 1 },
    { "key": "cards", "genreId": "411383", "genreLabel": "トレカ", "poolSize": 1, "trendingPoolSize": 1, "popularPoolSize": 1, "detectBrand": true }
  ],
  "period": "realtime",
  "historySize": 60,
  "referer": "https://x.com/",
  "maxPoolDisplay": 20,
  "trendingEnabled": true,
  "trendingRankJump": 5,
  "popularEnabled": true,
  "popularMinReviewCount": 50,
  "popularMinReviewAverage": 4.0,
  "targetTotalPicks": 10,
  "infoPosts": {
    "enabled": true,
    "maxPerDay": 1,
    "campaigns": [
      {
        "key": "5and0",
        "label": "5と0のつく日",
        "emoji": "🐬",
        "text": "本日は楽天市場の「5と0のつく日」!...",
        "url": "https://event.rakuten.co.jp/5and0/",
        "hashtags": ["5と0のつく日", "ポイ活"],
        "daysOfMonth": [5, 10, 15, 20, 25, 30]
      }
    ]
  }
}
```

- `genres`: 取得したいジャンルの配列。**1回の実行ごとに配列の各要素についてそれぞれ楽天ランキングAPIを叩き、投稿案をまとめてプールに追加する。** 要素を増減させれば好きなジャンルを何個でも組み合わせられる。
  - `key`: ジャンルを識別する英数字ID(急上昇検知のスナップショット保存に使うので、他の要素と重複しないユニークな値にする)。
  - `genreId`: 楽天ジャンルID。`0` は総合(全ジャンル)。特定ジャンルに絞りたい場合は
    [楽天ジャンル検索](https://webservice.rakuten.co.jp/explorer/api/IchibaGenre/Search/) や、
    楽天市場のカテゴリページURL末尾の数字から調べて差し替える(例: 家電=100804、コスメ=100939、ホビー(フィギュア・プラモデル・トレーディングカードなどサブカル系)=101164、トレーディングカード=411383 など。時期により変わるため要確認)。
  - `genreLabel`: 投稿文・ハッシュタグ・Webアプリのジャンルタブ/バッジに使う日本語ラベル(後述の`detectBrand`で上書きされる場合がある)。
  - `poolSize`: このジャンルで1回の実行あたり何件のランキング投稿案を新規追加するか。
  - `trendingPoolSize`: このジャンルで1回の実行あたり何件の急上昇商品を新規追加するか(`trendingEnabled: true` の場合)。
  - `popularPoolSize`: このジャンルで1回の実行あたり何件の「口コミ人気」商品を新規追加するか(`popularEnabled: true` の場合。詳細は後述)。
  - `detectBrand`: `true` にすると、商品名から「ポケカ」「ワンピカード」を自動判別してジャンルラベルを差し替える(後述)。トレカジャンル向けのオプション。
  - デフォルトでは「総合」「サブカル」(ホビージャンル。フィギュア・プラモデル・趣味コレクション等)に加えて「トレカ」(トレーディングカードジャンル。`detectBrand: true` によりポケカ・ワンピカードの商品は自動でそれぞれのラベルになる)が設定済み。不要なら配列から削除、他のジャンルを追加したい場合は上記のジャンルID検索で調べて要素を追加する。
- `period`: `realtime` / `daily` / `weekly` / `monthly` から選択(全ジャンル共通)。
- `historySize`: 直近何件を「提案済み」として重複を避けるか(ジャンルをまたいで共有される)。
- `referer` / `Origin`: 楽天アプリ登録時の「許可されたWebサイト」と一致させること。
- `maxPoolDisplay`: Webアプリに表示するプールの最大件数(古いものから溢れて消える。全ジャンル合算)。
- `trendingEnabled`: 順位急上昇検知を有効にするか(全ジャンル共通のON/OFF)。
- `trendingRankJump`: 前回スナップショットからこの順位数以上上がっていたら「急上昇」とみなす(新規ランクインは常に急上昇扱い。全ジャンル共通)。
- `popularEnabled`: 「口コミ人気」検知を有効にするか(全ジャンル共通のON/OFF)。
- `popularMinReviewCount` / `popularMinReviewAverage`: 「口コミ人気」として拾うレビュー件数・評価の下限(全ジャンル共通。詳細は後述)。
- `targetTotalPicks`: **1回の実行で必ずこの件数(既定10件)は投稿案を用意する。** 急上昇・口コミ人気が少ない(0件の)日でも、全ジャンルの合計がこの件数に届くまで、ランキング上位から順番に(ジャンルを1件ずつ回しながら)自動で補充する。全ジャンル合わせても新規候補が尽きた場合はそこで諦め、ログに警告を出す。
- `infoPosts`: アフィリエイトとは無関係な「お得情報」投稿の設定(詳細は後述)。

Webアプリ側は、プール内に2種類以上のジャンルが混在すると自動的に「ジャンル」タブとバッジを表示する(1ジャンルのみの構成なら今まで通り表示されない)。

補充頻度・時刻を変えたい場合は `.github/workflows/daily-post.yml` の `cron` を編集する(UTC指定なのでJSTから9時間引いた時刻)。

### セール検知・急上昇検知の仕組み

- **セール中バッジ**: 楽天ランキングAPIのレスポンスに含まれる `startTime`/`endTime`(期間限定セール)、`pointRate`(ポイントアップキャンペーン)を見て、現在その期間内かどうかを判定している(追加のAPI呼び出し・追加コストなし)。
- **急上昇バッジ**: 楽天には「話題の商品」を示す公式APIが無いため、代わりに**前回実行時の順位と比較して大きく順位が上がった商品**(新規ランクイン含む)を検知する自前ロジック(`src/trending.js`)。前回分の順位はジャンルごとに `src/rankSnapshot.json` に保存され(`{ "総合のkey": {...}, "サブカルのkey": {...} }` の形)、次回実行時にジャンルごとに比較される。**初回実行時(および新しくジャンルを追加した直後)はそのジャンルの比較対象が無いため急上昇は検知されない**(2回目以降から機能する)。
- **AIコメント**: `GEMINI_API_KEY` を設定すると、商品名・キャッチコピー・商品説明からGoogle Gemini(`gemini-3.7-flash`)が一言コメントを生成し、投稿文に添える(`src/comment.js`)。レビュー本文自体は楽天APIで取得できないため、実際のレビュー内容そのものを読んで書いているわけではない点に注意。キー未設定・生成失敗時はコメント無しの従来テンプレートに自動でフォールバックする。

### 「口コミ人気」検知の仕組み(ランキング順位に頼らない拾い方)

ランキング上位(①)・急上昇(②)に加えて、**③ 順位はさほど高くなくても口コミ(レビュー)件数が多く評価も高い = 購入頻度が高いと推測できる商品**を拾う仕組み(`src/popular.js`)。

- 各ジャンルのランキングAPI取得結果(上位30件程度)の中から、`reviewCount`(レビュー件数)が `popularMinReviewCount` 以上、かつ `reviewAverage`(平均評価)が `popularMinReviewAverage` 以上の商品を対象にする(低評価品がレビュー件数だけで紛れ込まないよう評価の下限も設けている)。
- 対象の中からレビュー件数が多い順に、ジャンルごとの `popularPoolSize` 件を新規追加する(①②で既に選ばれた商品は除外)。
- 追加のAPI呼び出しは発生しない(ランキングAPIのレスポンスに元々含まれる情報だけで判定)。
- Webアプリ上は「💬 口コミ人気」バッジ・タブで区別され、投稿文の見出しも「🏆 ○○の楽天人気ランキング」ではなく「💬 ○○の口コミで人気」になる(`#口コミ人気`ハッシュタグ付き)。

### ポケカ・ワンピカードなど、トレカの自動判別

トレーディングカードジャンル(`genreId: "411383"` など)は「ポケモンカード」「ワンピースカード」「遊戯王」等が入り混じった広いジャンルなので、`detectBrand: true` を付けたジャンルでは商品名から以下を判定し、ジャンルラベル(投稿文の見出し・ハッシュタグ・Webアプリのジャンルバッジ/タブ)を自動で差し替える(`src/cardBrand.js`)。

- 商品名に「ポケモンカード」「ポケカ」等を含む → ラベルを「ポケカ」に
- 商品名に「ワンピースカード」「ONE PIECEカード」等を含む → ラベルを「ワンピカード」に
- どちらにも一致しない場合 → ジャンルの既定ラベル(例: 「トレカ」)のまま

楽天のランキングAPIはジャンル単位でしか取得できずキーワード検索はできないため、あくまで**ジャンル内で実際にランクインした商品の商品名から事後的に判定**している(ポケカ・ワンピカードだけを狙い撃ちで検索しているわけではない)。Webアプリ側は2種類以上のラベルが混在すると自動でタブが増える(前述)ので、「ポケカ」「ワンピカード」がそれぞれ独立したタブ・バッジとして表示されるようになる。

### アフィリエイトとは無関係な「お得情報」投稿(インプレッション・閲覧数アップ目的)

商品ランキングとは別に、**特定商品・成果報酬に紐づかない楽天のお得情報**(例: 「5と0のつく日はポイントアップ」)も、該当日にはプールに自動追加される(`src/infoPosts.js`)。フォロワー向けの豆知識的な投稿でインプレッション・閲覧数を稼ぎたい、という用途を想定している。

- `config.json` の `infoPosts.campaigns` に、投稿したい情報を配列で登録しておく。各キャンペーンは以下のいずれかの条件を1つ持つ:
  - `daysOfMonth`: `[5, 10, 15, 20, 25, 30]` のように、毎月その日(JST)に該当すれば対象になる(「5と0のつく日」はこの形で標準搭載済み)。
  - `daysOfWeek`: `[0, 2]`(日曜=0〜土曜=6)のように、毎週その曜日に該当すれば対象になる。
  - `dateRange`: `{ "start": "2026-10-04", "end": "2026-10-11" }` のように、開催期間が決まっている単発イベント(お買い物マラソン・スーパーSALEなど)向け。楽天から開催情報が出たタイミングで手動で追加・削除する運用を想定している。
- `infoPosts.enabled`: 機能全体のON/OFF。`infoPosts.maxPerDay`: 複数のキャンペーンが同じ日に該当した場合、1回の実行で追加する上限件数。
- **ポイント倍率や割引率などの具体的な数値は本文にあえて書いていない**(このツールが自動生成する情報であり、楽天側の都合で時期によって変わりうるため、誤った数値を投稿し続けるリスクを避けている)。「詳細は公式ページで」という案内と、公式イベントページへのリンクのみを載せる形にしてあるので、正確な内容は必要なら `text` を直接編集して調整すること。
- **アフィリエイトリンクではなく成果報酬が発生しないため、`#PR` は付けない**(他の投稿と違い、ステマ規制の対象になる「広告」ではないため)。同じ理由で商品情報(価格・画像・レビュー等)も持たない。
- 同じキャンペーンでも投稿案の内部ID(itemCode)に日付が含まれるため、該当日ごとに(1日1回)また投稿案として追加される。Webアプリ上は「💡 お得情報」バッジ・タブで区別される。
- ①②③(ランキング・急上昇・口コミ人気)の**`targetTotalPicks`の枠外**として追加されるため、この機能をONにしても通常の商品ピック数が減ることはない。

### 複数端末(PC・スマホ)間で「投稿済み」を同期する

デフォルトでは「✅ 投稿済みにする」はその端末のブラウザ(localStorage)にしか記録されないため、
**PCで投稿済みにした商品が、スマホ側では未投稿のまま見えてしまい、重複ポストしてしまう**ことがある。
これを防ぐため、投稿済み状態をこのリポジトリの `docs/done.json` にも書き込んで、端末間で共有できるようにしている。

**設定方法(使う端末それぞれで1回だけ)**

1. [GitHubのFine-grained personal access token作成ページ](https://github.com/settings/personal-access-tokens/new) を開く。
2. **Repository access** を「Only select repositories」にして、このリポジトリ(`rakuten-x-poster`)だけを選択する。
3. **Permissions → Repository permissions → Contents** を `Read and write` に設定する(他の権限は不要)。
4. トークンを発行し、Webアプリの「⚙️ 同期設定」パネルに貼り付けて「💾 保存」する。
5. これで「投稿済みにする/戻す」を押すたびに `docs/done.json` が自動コミットされ、他の端末(同じトークンを設定した端末、または未設定の端末でも次回ページ読み込み時)に反映されるようになる。

**仕組みと注意点**

- 書き込みはGitHubの[Contents API](https://docs.github.com/en/rest/repos/contents)をブラウザから直接呼び出して行う(専用バックエンド不要)。設定した端末が「投稿済み」を押すたびに1コミットされる。
- 読み込み(ページを開いたとき)はトークン不要。GitHub PagesでホストされているHTMLと同様に `docs/done.json` を取得して手元のlocalStorageとマージするだけなので、トークンを設定していない端末でも「他の端末で投稿済みにした分」は反映される(ただしその端末発の変更はサーバー側に送られない)。
- GitHub Pagesの再デプロイには数十秒〜1分程度かかることがあるため、反映まで少しタイムラグがある。
- トークンはその端末のブラウザのlocalStorageに保存されるだけで、リポジトリやAIコメント生成などの他の用途には一切使われない。**他人と共有する端末では設定しない**こと(「🗑️ 解除」でいつでも削除できる)。トークン自体も「このリポジトリのContents読み書きのみ」に権限を絞ってあるので、万一漏れても影響範囲は限定的。
- 同期は「投稿済みにする/戻す」ボタンを押した操作ごとのAPI呼び出しのみで、自動投稿やスクレイピングの類ではないため、楽天アフィリエイト規約の「機械的な投稿の禁止」には抵触しない。

---

## 5. 法律・規約まわりの注意

- 2023年10月施行のステマ規制(景品表示法)により、アフィリエイト投稿だと分かるよう **#PR** を必ず入れている(`src/formatTweet.js`)。消さないこと。
  - 「お得情報」投稿(`src/infoPosts.js`)はアフィリエイトリンクを含まず成果報酬も発生しない、単なる情報発信のため `#PR` は付けていない。もし将来アフィリエイトリンク付きに変更する場合は、通常の投稿と同様 `#PR` を追加すること。
- **投稿ボタンは必ず自分の手で押すこと。** 完全自動投稿は楽天アフィリエイト規約違反のリスクがある(上記参照)。「お得情報」投稿も同じ仕組み(手動で「𝕏 で開く」を押す)に乗せている。
- 楽天アフィリエイトの規約で禁止されている行為(自己購入、他人の投稿へのリプライでのリンク掲載など)がないか、運用しながら適宜 [ガイドライン](https://affiliate.rakuten.co.jp/guideline/rule/) を確認すること。
- 「お得情報」投稿の本文・数値(ポイント倍率など)は、キャンペーン内容の変更に応じて `config.json` の `infoPosts.campaigns` を随時メンテナンスすること(このツールは自動で最新情報を取得しているわけではない)。

│   ├── history.json         # 提案済み商品コードの履歴(自動更新)

│   ├── index.html           # 専用Webアプリ本体(GitHub Pagesで公開、タブ切り替え・バッジ表示・端末間同期)
│   ├── pool.json            # 投稿案プールのデータ(自動更新)
│   └── done.json            # 投稿済みitemCodeの一覧(Webアプリから同期設定時のみ更新)
└── .github/workflows/
    └── daily-post.yml       # 毎日プールを補充するGitHub Actions定義
